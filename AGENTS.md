# Agent notes

## UI components (`@irshadnazree/just-things-ui`)

- **Default to `@irshadnazree/just-things-ui` for all UI components.** Always check its exports (`node_modules/@irshadnazree/just-things-ui/dist/index.d.ts` or `README.md`) and use package components (`AppHeader`, `AppHeaderBadge`, `Button`, `Input`, `Textarea`, `Select`, `NumberField`, `Checkbox`, `Switch`, `Slider`, `SegmentedControl`, `ChipGroup`, `Field`, `Surface`, `Glass`, `Tag`, `Table`, `Dialog`, `ConfirmDialog`, `Sheet`, `EmptyState`, `Progress`, `Spinner`, `Skeleton`, `ToastProvider`/`useToast`, `ThemeToggle`) instead of creating new local UI primitives or custom controls.
- **If no usable component exists, stop and tell the user.** Do not build a new custom UI component or local primitive in this repo when `@irshadnazree/just-things-ui` lacks a needed control, surface, overlay, or capability — let the user know what is missing so it can be added to `just-things-ui` first.
- **Composition and styling boundaries:** Local components under `src/components/` should only compose `@irshadnazree/just-things-ui` components for domain workflows. Use Tailwind and app CSS only for layout and arrangement (grid, flex, spacing, widths, positioning) with `--jt-*` theme tokens — never restyle package components, use raw colors, or add inline styles (enforced by `@shadcn/lint` in `oxlint.config.ts`).

## Checks and conventions

- Run `bun run check` (`oxlint .` + `oxfmt --check .`) and `bun run test` before committing (`bun run fix` auto-fixes lint and formatting; run `bun run build` when changing Vite, Cloudflare, or route config).
- Linting uses `oxlint` with `@cloudflare/oxlint-config`, `@interfere/landmines` (`landmines/no-comments: error` disallows casual inline `//` comments — use JSDoc `/** ... */` or `// WARNING: ...` only where genuinely warranted), and `@shadcn/lint`.
- `src/routeTree.gen.ts` is generated by `@tanstack/router-plugin` — do not edit it by hand.
